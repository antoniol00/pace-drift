## What this is

A concept-drift research PoC for network intrusion detection on the CIC-IDS2017 dataset. It compares three online-learning strategies for a Hoeffding Adaptive Tree (HAT) classifier as the underlying attack distribution shifts over the data stream:

- **Phase A** — Static model: pre-trained once, then frozen (predict-only).
- **Phase B** — Reactive model: HAT + Page-Hinkley Test (PHT) drift detector, retrains on a rolling window after each detected drift.
- **Phase C** — Proactive model: Phase B's strategy plus a lightweight `DriftGAN` (PyTorch GAN) that trains on recent attack samples at each detected drift and generates synthetic variations to augment retraining.

All three are prequential (test-then-train) evaluations over a streamed CSV, using `river` for online ML and PyTorch for the GAN.

## Repo structure and how it fits together

This directory is a working/output folder for notebook-generation scripts. The actual notebooks are *generated by* the `.py` scripts here but historically **executed and saved from a sibling directory**, `/mnt/AI-DATA-SSD/alara/CiberIA_O1_A1/CONCEPT_DRIFT/` — several scripts and in-notebook cells hardcode that absolute path for output (`.npz` result files, `.png` plots, and even the notebook file itself). When editing generator scripts, check the hardcoded output paths rather than assuming they write to the current directory.

- `create_gan_nb.py` — generates `HAT-PHT-GAN.ipynb` (Phase C) programmatically by assembling notebook cells as JSON (`nbformat`), rather than being hand-edited as a notebook. Contains the canonical `DriftGAN` class and the Phase C training loop.
- `create_eval_nb.py` — generates `HAT-PHT-COMPARE.ipynb`, which loads `results_ab.npz` and `results_c.npz` and plots all three phases (A/B/C) side by side.
- `update_ab_nb.py` — a one-off patch script that injects a "save results" cell into the existing `HAT-PHT-AB.ipynb` (this notebook itself is hand-authored/edited directly in Jupyter, not generated from a `.py` script like the other two).
- `HAT-PHT-AB.ipynb` — Phases A and B (static vs. reactive HAT+PHT), run against `CIC-IDS2017.csv`. Saves `results_ab.npz`.
- `HAT-PHT-GAN.ipynb` — Phase C (reactive HAT+PHT+GAN). Saves `results_c.npz`.
- `HAT-PHT-COMPARE.ipynb` — loads both `.npz` files and produces the combined comparison plot.
- `results_ab.npz`, `results_c.npz` — cached snapshot metrics (rolling F1, accuracy, per-interval CPU time, drift points) used to regenerate comparison plots without rerunning the full stream.
- `concept_drift_results.png`, `concept_drift_gan_results.png`, `concept_drift_COMPARE_results.png` — output plots from each notebook.

**Editing workflow**: because `HAT-PHT-GAN.ipynb` and `HAT-PHT-COMPARE.ipynb` are build artifacts of their corresponding `.py` scripts, prefer editing the generator script and re-running it (`python3 create_gan_nb.py`) over hand-editing the `.ipynb` JSON directly — otherwise the two get out of sync. `HAT-PHT-AB.ipynb` has no generator script and must be edited directly (as a notebook or by loading/mutating its JSON, as `update_ab_nb.py` does).

## Core experiment mechanics (shared across all three phases)

- **Data source**: `/mnt/AI-DATA-SSD/alara/Data/CIC-IDS2017.csv`, streamed row-by-row via a generator (`stream_csv`) rather than loaded into memory — the file is ~1.5GB.
- **Label binarization**: multiclass `Attack Type` is collapsed to binary `BENIGN` vs `ATTACK` in `preprocess_row`.
- **Stream offset**: reading starts at `START_ROW = 540_000` to skip the long initial all-benign block, so the first ~40K streamed rows are benign (for pre-training) before attack traffic (and thus drift) appears.
- **Pre-training**: first `N_PRETRAIN = 50_000` streamed rows are used for `learn_one` calls with no evaluation; prequential evaluation (predict-then-optionally-learn) starts after that point.
- **Drift detection** (Phases B & C): `river.drift.PageHinkley(delta=0.002)` monitors the 0/1 error signal; on `drift_detected`, the model re-enters a training-enabled window of `train_window = 5000` samples.
- **DriftGAN** (Phase C only): on each drift, if there are ≥5 buffered `ATTACK` samples in a `deque(maxlen=500)`, a small GAN (single-hidden-layer generator/discriminator, `noise_dim=16`) is trained for `epochs=30` on those samples and generates 200 synthetic attack samples, which are immediately fed into the tree via `learn_one` before the normal retraining window kicks in.
- **Metrics**: rolling F1 (custom `RollingF1`, binary, window=5000, positive label `ATTACK`) and cumulative `river.metrics.Accuracy`, snapshotted every `SNAP_INTERVAL = 500` samples along with per-interval wall-clock processing time (`time.perf_counter`).
